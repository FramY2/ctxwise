# v0.5.0 local context budget guard — TDD evidence

## User journey

As a Codex user, I want a local, reviewable context budget that warns or blocks
before an oversized known setup reaches an important task or CI, without
pretending unmeasured configuration or MCP schemas are zero tokens.

## RED

- Command: `npm test -- tests/unit/budget.test.ts tests/e2e/cli.test.ts`
- Result: `budget.ts` could not be imported and `ctxwise budget` was an unknown
  command.

## GREEN

- Unit coverage verifies deterministic token and largest-contributor limits,
  unknown-surface policy, strict versioned YAML, and the numeric-limit guard.
- Process coverage verifies a YAML policy, JSON output, and CI exit status `2`
  only with `--fail-on-exceed` and a blocking finding.
- The command reads the existing local audit surface only. It makes no model or
  network call, changes no Codex configuration, and does not read transcripts.
- Every displayed known-token value remains `estimated`; configuration/profile
  and MCP tool-schema surfaces remain `unknown` rather than becoming zero.

## Release review — 28 September 2026

- Three added regression tests initially failed: invalid programmatic numeric
  limits were accepted, an error snapshot could pass, and an unsorted supplied
  contributor list could hide its largest item.
- The evaluator now validates limits, reports audit errors as blocking unknown
  results, and selects the largest supplied contributor without relying on order.
- Added a process test using malformed TOML: the report remains unknown and
  `--fail-on-exceed` returns status 2. Without the flag it remains informational.
- The sample budget policy is included in the npm package, and release links
  point to the tagged source.
